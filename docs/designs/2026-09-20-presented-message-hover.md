# PresentedMessageView 悬停操作栏与消息时间设计

## 背景

用户需要在聊天消息上快速查看时间和复制正文。当前 `PresentedMessageView` 没有消息级复制入口，前后端消息契约也缺少统一时间字段。

本次已确认：

- 操作栏仅对 `agw-msg-user` 和 `agw-msg-result` 生效。
- 复制保留 Markdown 格式。
- 同步补齐消息时间的传输和历史映射。

## 设计目标

### 功能目标

1. 悬停目标消息时，在卡片外侧右下方显示时间和复制按钮。
2. 时间按用户本地时区显示为 24 小时制 `HH:mm`。
3. 点击复制按钮，将消息正文复制到剪贴板，保留 Markdown。
4. 新消息、流式消息和历史消息均支持时间展示。

### 技术目标

- 操作栏出现和消失时不改变消息高度，避免影响虚拟列表及滚动位置。
- 支持键盘聚焦和操作，按钮提供可访问名称。
- 同一消息的时间在流式追加、持久化和重放过程中保持稳定。
- 兼容旧客户端、旧服务端和既有历史数据。
- 复用现有组件、主题和剪贴板交互方式。
- 不新增依赖、配置项或数据库迁移；不改变消息排序和审计语义。

## 总体设计

本需求采用现有消息链路和共享 Web 渲染组件，不增加独立服务。

数据流如下：

1. 用户输入创建时记录时间；响应消息在产生时确定时间。
2. 时间随消息传输，并保存在现有消息 JSON 中。
3. 历史读取将持久化时间映射到消息输出；旧记录使用已有创建时间回退。
4. `PresentedMessageView` 格式化时间，并从展示模型提取可复制正文。
5. 操作栏通过 CSS 控制显隐，复制操作使用 Clipboard API。

Web 和 Desktop 共用上述界面能力；Mobile 本次不增加操作栏。

## 数据库设计

沿用现有历史表与 `ConversationPayload`，不新增表、列、索引或 Migration SQL。

| 存储位置 | 内容 | 用途 |
|---|---|---|
| `ConversationPayload` 内的 `AdditionalProperties.createdAt` | 带时区的 RFC 3339 时间 | 保存消息展示时间 |
| 历史记录已有 `CreateTime` | 记录创建时间 | 旧数据缺少消息时间时回退 |

已有记录无需批量回填。旧历史回退展示的是记录创建时间，无法恢复过去未记录的精确发送时间。

客户端传入的消息时间只用于展示，不覆盖数据库审计字段，也不参与授权或消息排序。

## 详细设计

### 悬停显示操作栏

修改 `PresentedMessageView`：

- 沿用现有 `isUser`、`isResult` 判断，仅为目标消息渲染操作栏。
- 将消息卡片设为定位容器，操作栏绝对定位于卡片外侧右下方，使用现有底部间距。
- 操作栏依次显示灰色时间文字和复制图标，沿用项目主题与 `Button`。
- 默认透明并禁止鼠标点击；悬停消息或焦点进入消息内部时显示。
- 操作栏与卡片之间保持连续的鼠标可达区域，移向按钮时不会消失。
- 键盘可聚焦复制按钮，聚焦后显示操作栏。

不改变现有卡片宽度、正文布局和 Result 标题样式。

### 复制消息正文

从渲染 `agw-msg-body` 所使用的 `message.contents` 提取内容，不直接读取 DOM 文本，避免复制到按钮文字或丢失 Markdown。

| 正文类型 | 复制规则 |
|---|---|
| Markdown | 保留原 Markdown |
| Plain、Error、JSON | 使用展示模型中的文本 |
| Reasoning | 使用完整推理文本 |
| Plan | 按顺序包含前文、计划正文、后文 |
| 独立 Image、URI 图片附件 | 不转换为文本 |

多个文本块按原顺序以空行连接；保留块内换行和代码缩进。复制范围不包含 Result 标题、正文外引用、目录信息或操作栏。

点击时复制当前正文，包括流式消息已经收到的内容：

- 成功后将 Copy 图标切换为 Check，2 秒后恢复。
- 重复复制时重新计时；组件卸载时清理计时器。
- 失败时使用现有 toast 提示，不显示成功状态。
- 没有可复制文字时禁用按钮。

### 补齐消息时间

统一使用 `createdAt` 表示消息展示时间。

**用户输入**

- 前端创建消息时记录 UTC 时间，并随执行输入传递。
- 服务端创建对应消息时保留该时间。
- 旧客户端没有传入时，通过 `TimeProvider` 在接收输入时补齐。

**响应与 Result**

- 优先使用提供方返回的消息创建时间。
- 提供方未返回时间时，通过 `TimeProvider` 记录首次接收到该消息的时间。
- 服务端自行生成的 Result 在创建时记录时间。
- 时间应在消息进入历史收集和客户端输出之前确定，覆盖内置 Agent、外部 Agent 及 Agentflow 输出路径。

**流式与历史**

- 沿用现有消息身份和执行作用域，保留同一消息首次确定的时间。
- 后续分片不覆盖已有时间；首个分片缺失时间时允许补入后续有效值。
- 克隆、聚合、持久化、恢复和重放均保留该值。
- 历史读取优先使用 JSON 中的消息时间，缺失时使用记录 `CreateTime`。
- 持久化使用现有 JSON 扩展属性，客户端输出映射到顶层 `createdAt`。

### 本地时间展示与兼容

- 前端使用现有日期解析工具，将 `createdAt` 转为本地时间，再格式化为 `HH:mm`。
- 小时和分钟均补齐两位，午夜显示 `00:00`。
- 时间缺失或无效时隐藏时间文字，复制按钮仍可用。
- 不使用组件挂载时间代替消息时间。
- 新字段保持可选，旧调用方无需立即升级；旧客户端可以忽略新增字段。

## 接口文档

### 基础信息

- 不新增 HTTP 路由或 SignalR 方法。
- 沿用现有域名、认证、授权和请求头。
- HTTP JSON 响应继续使用 Bens.Results；SignalR 保持原协议。
- 修改共享输入和输出契约，并更新前端类型及 OpenAPI 生成产物。

### 接口列表

| 现有协议位置 | 修改内容 | 兼容性 |
|---|---|---|
| 用户执行输入 `AgwUserInput` | 新增可选 `CreatedAt` | 未传时由服务端补齐 |
| 执行消息输出 `AgwMessage` | 新增可选 `CreatedAt` | 旧客户端忽略新增字段 |
| 对话、任务历史消息输出 | 返回消息时间或历史创建时间 | 无数据库迁移 |
| 前端 `AiMessage`、`ExecutionMessage`、执行输入类型 | 增加可选 `createdAt` | 兼容旧服务端缺少字段 |

后端类型为 `DateTimeOffset?`，前端类型为 `createdAt?: string | null`。线上 JSON 使用 `createdAt`。

用户输入示例，以下为协议字段片段：

```json
{
  "messageId": "message-id",
  "author": "$agw",
  "createdAt": "2026-09-19T13:38:00Z",
  "contents": [
    {
      "type": "TextContent",
      "content": "请解释 **Middleware**"
    }
  ]
}
```

消息输出示例：

```json
{
  "messageId": "result-id",
  "role": "assistant",
  "createdAt": "2026-09-19T13:38:12Z",
  "additionalProperties": {
    "type": "result"
  },
  "contents": [
    {
      "type": "TextContent",
      "content": "## 说明\n\nMiddleware 用于……"
    }
  ]
}
```

上述时间在新加坡时区显示为 `21:38`。

## 测试计划

### 单元测试

| 用例 | 前置条件与操作 | 预期结果 |
|---|---|---|
| 操作栏适用范围 | 分别渲染用户、Result、普通助手和工具消息 | 仅前两类包含操作栏 |
| Markdown 复制 | 正文包含标题、列表、链接和代码块，点击复制 | 剪贴板保留 Markdown 与缩进 |
| 多块正文复制 | 混合文本、JSON、计划与图片 | 文本按顺序连接，JSON 保持展示值，图片被跳过 |
| 复制状态 | 模拟成功、重复点击和剪贴板拒绝 | 成功图标按时恢复，失败显示提示 |
| 纯图片消息 | 正文无文字 | 复制按钮禁用 |
| 时间格式化 | 固定时区，传入正常时间、午夜、无效值 | 分别显示正确 `HH:mm`、`00:00` 或隐藏时间 |
| 时间默认值 | 输入未提供时间，使用可控 `TimeProvider` | 服务端补齐确定时间 |
| 流式时间合并 | 同一身份连续追加分片，再模拟跨轮复用 ID | 本消息时间稳定，不串到其他执行作用域 |
| 历史兼容 | 分别读取包含时间和缺少时间的历史记录 | 优先使用消息时间，否则使用 `CreateTime` |

### 集成测试

使用现有假 Agent 和历史测试设施：

- 验证用户输入时间从客户端协议传递到服务端消息及历史输出。
- 验证内置、外部 Agent 和 Agentflow 的 Result 时间能够进入消息输出与持久化。
- 验证流式快照、最终保存、历史重新读取和事件重放保留同一时间。
- 验证旧输入和旧历史记录仍能正常处理。
