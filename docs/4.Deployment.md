# Agw Server Deployment

Agw production releases run as one ASP.NET Core process. The Server hosts the API, WebSocket endpoints, setup pages, and the statically exported Web UI. Node.js is required only while building the release.

## Data directory

Portable releases store mutable data in the current user's `agw` directory:

- Windows: `%USERPROFILE%\agw`
- macOS and Linux: `~/agw`
- Container: `/data`

Set `AGW_DATA_DIR` to override the default. Back up `server-state.json`, `database/`, `skills/`, and `keys/` together. Logs and temporary files do not need to be restored.

## Portable Server

Start the extracted package with `agw-server serve` (`agw-server.exe serve` on Windows). Running without the `serve` argument remains supported. It listens on `http://127.0.0.1:5015` unless `ASPNETCORE_URLS` is set.

Reset a forgotten administrator password while the Server is stopped:

```bash
agw-server auth reset-password
```

## Container

Build and run the single-process image:

```bash
PUBLISH_MODE=docker IMAGE_NAME=agw:latest ./publish.sh
docker load -i artifacts/publish/docker/agw-server-0.1.0-local-linux-arm64.tar
docker run --rm -p 127.0.0.1:5015:8080 -v agw-data:/data agw:latest-arm64
```

The default build writes loadable Linux amd64 and arm64 image archives. Set `DOCKER_PUSH=true` to publish a multi-platform manifest under `IMAGE_NAME` instead.

The first startup prints a one-time remote Setup Code. Direct `localhost` setup does not require the code.

## Domain access

Terminate TLS with Caddy or Nginx on the host and proxy to `127.0.0.1:5015`. Keep the Agw HTTP port bound to loopback, preserve the original Host, and forward scheme/client headers. Set `AllowedHosts` to the public hostname. Loopback proxies are trusted by default; add any other proxy IP through `ReverseProxy__TrustedProxies`. The Compose example uses a fixed Docker gateway and trusts only that gateway. See `deploy/Caddyfile.example`, `deploy/nginx.conf.example`, and `deploy/compose.yaml`.

Agw v1 supports a dedicated domain root such as `https://agw.example.com/`. Deploying below a path such as `/agw`, direct certificate management by Agw, and multiple Server replicas without Redis are not supported.

## Upgrading existing installations

No database schema migration is part of this deployment change. Stop the old Server and back up its files before upgrading.

- SQLite: copy the old database to `agw/database/agw.db`, or enter its absolute path during setup.
- PostgreSQL/MySQL: enter the existing connection string during the new setup.
- Skills: copy the old `wwwroot/skills` contents to `agw/skills`.
- Authentication: the old `X-API-Key` is not migrated. Create a new administrator password and named API Tokens.
