**Events** is the event hub behind Jobs and external triggers. It accepts CloudEvents from configured sources, matches them against user-owned subscriptions, dispatches work to Agents, Agentflows, or extension handlers, and records every delivery attempt. **Notifications** collects notices and interactive questions generated by runs or extensions and delivers them in real time to Web, Desktop, and configured notification channels.

Open **Events** or **Notifications** from the Web navigation under **Activity**, or from the Desktop Ribbon.

## Event Center

The Events page is organized into four tabs:

| Tab | What it manages |
| --- | --- |
| **Events** | Accepted CloudEvents, filterable by `Type`, `Subject`, and `ChainId`, with payload and linked deliveries |
| **Sources** | Event producers: `Timer`, `Webhook`, `HTTP poll`, `Extension provider`, and `Publisher` |
| **Subscriptions** | Filter rules and target bindings (Agent, Agentflow, or extension handler) |
| **Deliveries** | Dispatch records with states (`Pending`, `Running`, `Waiting for execution`, `Succeeded`, `Retry scheduled`, `Held`, `Parked`, `Cancelled`) and **Retry** / **Cancel** actions |

### Create sources and subscriptions

1. In **Sources**, create a `Timer`, `Webhook`, or `HTTP poll` source. When creating a `Webhook` source, copy the generated ingest URL and secret shown after creation. `Timer` sources created by Jobs and extension-owned records carry a managed badge and are edited through their owning page or extension.
2. In **Subscriptions**, create a subscription, set optional filter criteria (event type, subject, source), and choose the target Project and Agent or Agentflow (or extension handler).
3. Trigger or publish a test event, inspect its record under **Events**, and verify the resulting entry under **Deliveries**.

When a retryable delivery exhausts `Events:Delivery:MaxAttempts`, it enters the `Parked` state. Fix the underlying target or configuration issue, then click **Retry** on the delivery in **Deliveries**. Split deployments require Redis for `Events:Transport:Provider` so Control Plane workers and Data Plane publishers share events.

## Notification Center

Notifications appear in **Notifications** with an unread badge in the sidebar and live updates over SSE (`Notifications:Stream:PollInterval`). Desktop also surfaces incoming notifications through OS system notifications for the active Server profile and user.

- Read notices and mark them as read, or inspect their source context.
- Answer interactive prompts directly inside the notification entry when a run or extension (such as TaskPilot) requests a decision or reply.
- Configure external notification channels (such as Feishu) by installing and enabling the corresponding [Server extension]({{< relref "/docs/operations/extensions" >}}).
