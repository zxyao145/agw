# Agw OAuth2 登录能力扩展

状态：待实施设计。现有 OIDC 实现保持不变。

## 名词解释

| 名词 | 说明 |
| --- | --- |
| OIDC | 在 OAuth2 基础上提供 ID Token 和标准身份声明的协议 |
| OAuth2 | Authorization Code 等授权流程的协议，本身不规定统一身份信息格式 |
| UserInfo | 使用 access token 获取用户身份信息的接口 |
| JWT access token | 带签名、issuer、audience 和有效期的 access token |
| PKCE | 使用 code_challenge 和 code_verifier 保护授权码流程 |

C# 中使用枚举，配置文件中使用字符串：

~~~csharp
public enum AuthProviderType
{
    Oidc,
    OAuth2,
}

public enum OAuth2ClientAuthMethod
{
    Post,
    Basic,
}

public enum OAuth2IdentitySource
{
    UserInfo,
    AccessToken,
}
~~~

## 背景

当前 Provider 统一使用 OIDC Handler，依赖 Authority、OIDC discovery、ID Token 和 issuer/sub。GitHub 使用 OAuth2 Authorization Code 和 UserInfo /user，不依赖 ID Token，因此需要新增通用 OAuth2 配置。[GitHub OAuth 文档](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)

本方案只扩展 Server、Web 和 Desktop 的认证能力，不改变本地用户、Token、权限和数据库模型。

## 设计目标

### 功能目标

- Provider 支持 Oidc 和 OAuth2；未配置 Type 时兼容为 Oidc。
- 支持 OAuth2 Authorization Code。
- UsePkce 为 true 时使用 S256，为 false 时不发送 PKCE 参数。
- OAuth2 身份来源支持 UserInfo 和已验证 JWT AccessToken。
- Token Endpoint 客户端认证支持 Post 和 Basic。
- 支持 GitHub OAuth2。
- Web 创建 Agw Cookie，Desktop 继续使用一次性交换码获取 Agw Token。
- Provider 列表返回字符串形式的 type。
- 不通过 email 关联用户，不增加 Mobile 独立流程。

### 技术目标

- PKCE 只允许 S256。
- JWT 必须验证签名、issuer、audience、exp 和 nbf；opaque token 直接拒绝。
- Token/UserInfo 请求超时 15 秒，登录流程最长 10 分钟。
- 不记录 Secret、授权码、Token、verifier 和完整回调参数。
- 保持 state、correlation、CSRF、限流、Cookie 和 Desktop grant 防护。
- 外部失败时不创建用户、Cookie 或 Desktop grant。
- 增加 OAuth2 登录、换码、UserInfo、JWT 校验和 PKCE 指标。
- 不新增数据库对象或 Migration。

## 总体设计

### 方案对比与技术选型

| 方案 | 结论 |
| --- | --- |
| 所有 Provider 使用 OIDC Handler | 无法处理无 ID Token 的 OAuth2 平台 |
| 每个平台独立 Adapter | 平台越多重复代码越多 |
| OIDC Handler + 通用 OAuth2 Handler | 采用，按 Provider 类型选择 Handler |

~~~mermaid
sequenceDiagram
~~~

沿用上例，将配置改为：

~~~json
{
  "IdentitySource": "AccessToken",
  "UsePkce": true,
  "ClientAuthMethod": "Post"
}
~~~

此模式同时验证 authorization code、PKCE verifier 和 JWT access token。

### Handler、Token 交换和 PKCE

根据 AuthProviderType 选择 OIDC Handler 或 OAuth2 Handler，Scheme 分别为 oidc:providerId 和 oauth2:providerId，回调路径保持 /api/auth/oidc/callback/{providerId} 兼容现有客户端。

Post 将 client_id 和 client_secret 放入 Token 请求体；Basic 使用 HTTP Basic Authorization Header。Token 响应支持 JSON 和 form-urlencoded。

UsePkce 为 true 时生成高熵 verifier，发送 S256 challenge，并在 Token 请求中发送 verifier；为 false 时不发送这些参数。两种模式都校验 state、correlation 和 authorization code。

### 身份获取与本地用户

UserInfo 模式使用 Bearer access token 请求 UserInfoEndpoint，按 SubjectClaim、DisplayNameClaim 和 EmailClaim 读取字段；subject 必须存在。

AccessToken 模式必须配置 AccessTokenIssuer、AccessTokenAudience 和 AccessTokenJwksUri，并验证 JWT 签名、issuer、audience、exp 和 nbf。只 Base64 解码 JWT 或使用 opaque token 均拒绝。

OAuth2 issuer 使用配置中的稳定 Issuer，subject 来自 UserInfo 或已验证 JWT，继续按 issuer + subject 查找本地用户，不按 email 关联。新用户 ID 继续从 10000 开始。

### Web、Desktop、安全、缓存和可观测性

- Web 和 Desktop 继续使用现有登录入口；Desktop 的 OAuth2 PKCE 与 Desktop grant PKCE 是两套独立凭据，第三方 access token 不返回 Desktop。
- verifier 不进入 URL、日志或数据库明文；生产外部端点必须 HTTPS；Provider disabled 时禁止新登录和未完成 grant 兑换。
- OIDC discovery 使用框架缓存；JWT JWKS 缓存 5 分钟，未知 kid 时允许一次刷新；不缓存 UserInfo 和本地 session version。
- 新增 agw.auth.oauth2.login、token_exchange、userinfo、access_token_validation、pkce 和 callback.duration 指标。
- 日志只记录 Provider、client、阶段、错误类别、异常类型和 TraceId，禁止记录 Secret、授权码、Token、verifier 和完整上游响应。

## 接口文档

### 基础信息

| 项目 | 约定 |
| --- | --- |
| 本地地址 | http://127.0.0.1:30816 |
| 生产地址 | https://<public-host> |
| Web 认证 | HttpOnly Agw Cookie |
| Desktop 认证 | Authorization: Bearer agw_... |
| 登录入口 | /api/auth/oidc/login |
| 回调入口 | /api/auth/oidc/callback/{providerId} |
| JSON 响应 | Bens.Results |
| Callback 响应 | 302 Redirect |

### Provider 列表

~~~http
GET /api/auth/oidc/providers
~~~

~~~json
{
  "code": 0,
  "title": "ok",
  "statusCode": 200,
  "data": [
    {
      "id": "google",
      "displayName": "Google",
      "type": "Oidc"
    },
    {
      "id": "github",
      "displayName": "GitHub",
      "type": "OAuth2"
    }
  ]
}
~~~

type 序列化为字符串，旧客户端可以忽略新增字段。

### 发起登录

~~~http
GET /api/auth/oidc/login?providerId=github&client=web&returnUrl=/dashboard/
~~~

Desktop 额外提交 clientState、codeChallenge 和 codeChallengeMethod=S256。Type 只从 Server 配置读取，不接受客户端传入。

### OAuth2/OIDC 回调

~~~http
GET /api/auth/oidc/callback/{providerId}?code=<authorization-code>&state=<state>
~~~

Web 成功后创建 Cookie；Desktop 成功后重定向到 agw-desktop://auth/complete。

### Desktop Token 交换

~~~http
POST /api/auth/desktop/exchange
Content-Type: application/json
~~~

~~~json
{
  "code": "<one-time-code>",
  "codeVerifier": "<desktop-verifier>"
}
~~~

OAuth2 Server verifier 与 Desktop verifier 独立，第三方 access token 不出现在响应中。
