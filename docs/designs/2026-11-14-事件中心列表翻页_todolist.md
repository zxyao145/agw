# 事件中心列表翻页：实施计划

> **给执行计划的 agent：** 必须使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 按任务逐个实施。步骤使用 checkbox（`- [ ]`）记录进度。

**目标：** 六个事件列表接口返回 `PagedResult<T>`，Events 页面的六个列表各自翻页，每页条数可选 10、20、50、100。

**架构：** 后端由 `PageValidation` 校验翻页参数，`EventPaging` 在数据库中计数和分页。`EventManagementAppService`、`EventSourceAppService` 和 `EventRecoveryControl` 的列表方法使用 `EventPaging`，Waiting records 用 `UNION ALL` 合并三类记录后分页。前端共享组件 `TablePagination` 增加 `pageSizeOptions`，Events 页面通过 `useEventListPage` 保存每个列表的页码和每页条数。

**技术栈：** .NET 10、ASP.NET Core Minimal API、EF Core（SQLite、PostgreSQL）、xUnit v3、React、TanStack Query、Node test runner（`tsx --test`）。

**设计文档：** `docs/designs/2026-11-14-事件中心列表翻页.md`。执行每个任务之前阅读设计文档的对应章节。

## 全局约束

- 没有兼容性要求：六个列表接口直接改为翻页格式，`GET /api/events/list` 删除 `Offset`、`Limit`。不修改表结构，不增加 migration。
- 翻页参数：页码从 1 开始，默认 1；每页条数只接受 10、20、50、100，默认 20。
  - `pageIndex < 1`：`AgwException(ErrorCodes.InvalidParam, "pageIndex must be at least 1.")`。
  - 每页条数不在列表中：`AgwException(ErrorCodes.InvalidPageSize, "pageSize must be one of 10, 20, 50, or 100.")`。
  - 不新增错误码。
- 查询参数名：`GET /api/events/list` 使用 `PageIndex`、`PageSize`（沿用 `EventListQuery` 的属性命名）；其余五个列表接口使用 `pageIndex`、`pageSize`。
- 排序，每个都以唯一键结尾：
  - Events：`ReceivedAt` 降序、`Id` 降序。
  - Sources、Subscriptions：`Name`、`Id`。
  - Deliveries：`Id` 降序。
  - Schedules：`DueAt == null`、`DueAt`、`Id`。
  - Waiting records：`RecoverAfter`、`EntityId`。
- 页码超过最后一页时返回空的 `Items` 和实际的 `Total`。
- 接口返回 Bens.Results（`ApiResult.Ok(...)`），参数放在 query 中。用户隔离沿用现有查询条件和 user-scope 查询过滤器，不增加 `userId` 参数。
- 前端：Events 页面使用 `EVENT_PAGE_SIZE_OPTIONS = [10, 20, 50, 100]`，默认每页 20 条；其他页面继续使用 `PAGE_SIZE_OPTIONS`（10、20、50）。
