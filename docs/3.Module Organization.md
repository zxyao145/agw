
# 模块组织

Agw 是一个模块化单体，并使用 Clean Architecture 分层。模块仅需要创建其实际所需的层，不要求创建空层，也不要求完整照搬 Clean Architecture 的全部形式。

## 后端架构和模块分层

后端模块按业务领域拆分，模块内的分层方向是:

```text
Api → 应用层 → 领域层 ← 基础设施层
```

每个模块只创建其所需的层。

- Api 层  
包含 Controller，Endpoint，DTO，Validator。
- 应用层  
包含 Use cases，workflow，服务 orchestration，和 Domain 规则调用
- 领域层  
包含 贫血实体、值对象、无框架依赖的 Behaviors 和跨实体边界 DomainServices。

## 跨模块调用

跨模块调用的固定路径：

```plaintext
调用方 
→ Agw.<Module>.Contracts 中的接口 
→ 所属模块的 Facade（在所属模块的 Add<Module>() 中注册）
→ 模块内部的 AppService 或 I<Module>DbContext
```

如无特殊说明，跨模块调用只能经过对方的 Agw.&nbsp;.Contracts 接口，接口由对方模块的 Facade 实现。

- Contracts 项目只放接口和 DTO，只依赖 Agw.Shared 或其他 Contracts。
- 禁止引用其他模块的 Application、Domain、Infrastructure 命名空间。
- 禁止引用其他模块的 *AppService、*RuntimeService、I&nbsp;DbContext。

## 贫血领域模型

持久化实体，领域数据对象，值对象，等必须保持贫血模式，对于贫血模型所需要的行为，需压放在实体上所属 Module 的 `Domain/Behaviors/<Entity>Behavior.cs` 中。

### Behavior 构造和生命周期

Behavior 用来构造贫血模型的行为，`Behavior = 聚合根的充血模型`：

```
public class Order
{
    public Guid Id { get; set; }

    public OrderStatus Status { get; set; }

    public List<OrderItem> Items { get; set; }

    public decimal TotalAmount { get; set; }
}

public class OrderBehavior
{
    private readonly Order _order;
    
    public OrderBehavior(Order order)
    {
        _order = order;
    }

    public void Submit()
    {
        if (_order.Status != OrderStatus.Pending)
            throw new DomainException("订单当前状态不允许提交");

        if (_items.Count == 0)
            throw new DomainException("空订单不能提交");

        _order.Status = OrderStatus.Submitted;
    }

    public void Cancel()
    {
        if (_order.Status == OrderStatus.Completed)
            throw new DomainException("已完成订单不能取消");

        if (_order.Status == OrderStatus.Cancelled)
            return;

        _order.Status = OrderStatus.Cancelled;
    }
}
```

- 实体绑定的 Behavior **必须**是具体的 `<Entity>Behavior` 类并且 **必须** 由 Application 或 DomainService 代码使用 `new` 手动创建。
- Behavior 构造函数恰好绑定一个聚合根。根本地前置条件 MAY 在加载所属子项之前运行; Application 或 DomainService 必须在调用任何检查或修改这些子项的 Behavior 方法之前加载完整的一致性边界。
- Behavior 可以修改绑定的聚合根及其所属子项。它禁止修改外部实体。
- 外部事实，时间，和参与者身份，必须由 Application 或 DomainService 解析并作为值或只读上下文传递给 Behavior 方法。
- Behavior **禁止**注册到 IoC，缓存，序列化，在线程间共享，或跨用例复用。
- Behavior **禁止**定义 `I<Entity>Behavior` Interface，除非存在两个真实的 Adapters 并且架构决策已被明确批准。

### DomainService

DomainService 用于明确属于领域业务规则，但又不自然属于某一个 聚合根 / Entity / Value Object 的行为。

```
public sealed class UserDomainService
{
    private readonly IUserRepository _users;

    public UserDomainService(IUserRepository users)
    {
        _users = users;
    }

    public async Task<User> CreateAsync(
        string userName,
        Email email,
        CancellationToken cancellationToken = default)
    {
        if (await _users.ExistsByEmailAsync(
                email,
                cancellationToken))
        {
            throw new DomainException(
                $"Email '{email}' 已被使用");
        }

        if (await _users.ExistsByUserNameAsync(
                userName,
                cancellationToken))
        {
            throw new DomainException(
                $"UserName '{userName}' 已被使用");
        }

        return new User(
            UserId.New(),
            userName,
            email);
    }
}
```

## 持久化

使用模块化的 DbContext 接口，每个模块都声明自己的 `I<Module>DbContext`，都放在各模块的 `Application/Persistence` 下。它们都继承 `IModuleDbContext`，这个基接口只有 `SaveChangesAsync`方法。

- `I<Module>DbContext` 接口中除了继承的接口，只有 DbSet 属性。
- 所有`I<Module>DbContext`的实现，都放在 `Infrastructure` 模块（注意，不是当前模块的 基础设施层）中 。
- 业务模块只通过自己的 I&nbsp;DbContext 访问数据。需要复用的复杂持久化逻辑，或者跨所属模块的事务：在 `Application/Persistence` 中声明接口，在 `Agw.Infrastructure/<Module>/` 中实现。
- 持久化拦截器：
  - EntityCreatorInterceptor：填写 CreateBy 和 CreateTime，并校验所有者。
  - EntityModifierInterceptor：CreateBy 不能修改；校验所有者；填写 UpdateBy 和 UpdateTime，已经显式修改的值保留不动。
  - EntitySoftDeleteInterceptor：把 ISoftDelete 实体的删除改为更新。当前没有实体实现 ISoftDelete，所以所有删除都是物理删除。
- 数据库中，列名使用 snake_case 命名法。
- 数据库不建立外键，通过 `NoForeignKeyModelDiffer` 实现。
