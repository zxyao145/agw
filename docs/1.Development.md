# Build And Development Commands

## Backend

### Commands

Run from the repo root:

```bash
dotnet restore Agw.slnx
dotnet build Agw.slnx
dotnet run --project src/backend/Agw.Host
dotnet watch --project src/backend/Agw.Host
dotnet test Agw.slnx
dotnet format
```

Notes:

- The development host launches on `http://localhost:5015` by default via `src/backend/Agw.Host/Properties/launchSettings.json`.
- Do not add or apply EF Core migrations automatically. When needed, use:

```bash
dotnet ef migrations add <MigrationName> \
  -p src/backend/Agw.Infrastructure \
  -s src/backend/Agw.Host

dotnet ef database update \
  -p src/backend/Agw.Infrastructure \
  -s src/backend/Agw.Host
```

### Tests

```bash
# Run all tests
dotnet test Agw.slnx
```

### Backend Exceptions

Backend code uses a centralized exception model in `src/backend/Agw.Shared/Exceptions/`:

- `AgwException` carries `int Code`, `HttpStatusCode StatusCode`, and the exception message. `StatusCode` defaults to `HttpStatusCode.BadRequest` when a constructor does not receive one.
- `ErrorCode` is `public record ErrorCode(int Code, string Message, HttpStatusCode StatusCode)`.
- `ErrorCodes.cs` is the only catalog for reusable backend error codes.

When adding or changing backend exception handling:

1. Use `throw new AgwException(ErrorCodes.SomeCode)` for expected validation, domain, application, scheduler, tool, or runtime failures.
2. Use `throw new AgwException(ErrorCodes.SomeCode, "...")` when the message needs runtime context. Keep the `ErrorCodes` catalog message generic enough to reuse.
3. Do not add new explicit `throw new ArgumentException`, `InvalidOperationException`, `NotSupportedException`, `HttpRequestException`, `FileNotFoundException`, `DirectoryNotFoundException`, `UriFormatException`, or protocol-specific exceptions in `src/backend` for expected application failures.
4. Reuse existing `ErrorCodes` entries when possible. Add a new entry only when the failure is meaningfully distinct for API clients, logs, or tests.
5. New `ErrorCode.Code` values must be 7 digits. The first 3 digits must equal the HTTP status code, and the final 4 digits increment within that status group. Examples: `400_0001`, `404_0003`, `500_0010`.
6. Do not renumber existing error codes. Append the next value in the matching status-code group.
7. Keep boundary-specific protocol behavior at the boundary. A2A internals throw `AgwException`; `AgwA2AJsonRpcProcessor` maps those to A2A JSON-RPC errors. Controllers that need custom HTTP responses should catch `AgwException`.
8. Update tests to assert `AgwException.Code` and `StatusCode` instead of framework exception types. Run `dotnet test tests/Agw.Shared.Tests/Agw.Shared.Tests.csproj` after changing exception rules or error codes.

## Frontend

### Commands

Run from `src/frontend/web`:

```bash
pnpm install
pnpm dev
pnpm build
pnpm lint
pnpm lint:fix
pnpm format
pnpm format:check
pnpm gen:openapi
```

Notes:

- The Next.js dev server runs on `http://localhost:3000` by default.
- `src/frontend/web/next.config.ts` rewrites `/api/*` and `/openapi/*` to `BACKEND_API_BASE_URL` (default `http://localhost:5015`).
- Regenerate `src/frontend/web/src/api/openapi.d.ts` after backend contract changes.
