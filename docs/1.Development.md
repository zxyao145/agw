# Build And Development Commands

## Backend

### Commands

Run from the repo root:

```bash
dotnet restore Agw.slnx
dotnet build Agw.slnx
dotnet run --project src/server/Agw.Host
dotnet watch --project src/server/Agw.Host
dotnet test Agw.slnx
dotnet format
```

Notes:

- The development host launches on `http://localhost:30815` by default via `src/server/Agw.Host/Properties/launchSettings.json`.
- `DistributedLock:Provider` may be `inmemory` or `postgres`. Leave it null or omit it to derive the lock from the current database provider; an empty PostgreSQL lock connection string reuses the current database connection string.
- Do not add or apply EF Core migrations automatically. When needed, use:

```bash
dotnet ef migrations add <MigrationName> \
  -p src/server/Agw.Infrastructure \
  -s src/server/Agw.Host

dotnet ef database update \
  -p src/server/Agw.Infrastructure \
  -s src/server/Agw.Host
```

### Backend Exceptions

Backend code uses a centralized exception model in `src/server/Agw.Shared/Exceptions/`:

- `AgwException` carries `int Code`, `HttpStatusCode StatusCode`, and the exception message. `StatusCode` defaults to `HttpStatusCode.BadRequest` when a constructor does not receive one.
- `ErrorCode` is `public record ErrorCode(int Code, string Message, HttpStatusCode StatusCode)`.
- `ErrorCodes.cs` is the only catalog for reusable backend error codes.

When adding or changing backend exception handling:

1. Use `throw new AgwException(ErrorCodes.SomeCode)` for expected validation, domain, application, scheduler, tool, or runtime failures.
2. Use `throw new AgwException(ErrorCodes.SomeCode, "...")` when the message needs runtime context. Keep the `ErrorCodes` catalog message generic enough to reuse.
3. Do not add new explicit `throw new ArgumentException`, `InvalidOperationException`, `NotSupportedException`, `HttpRequestException`, `FileNotFoundException`, `DirectoryNotFoundException`, `UriFormatException`, or protocol-specific exceptions in `src/server` for expected application failures.
4. Reuse existing `ErrorCodes` entries when possible. Add a new entry only when the failure is meaningfully distinct for API clients, logs, or tests.
5. New `ErrorCode.Code` values must be 7 digits. The first 3 digits must equal the HTTP status code, and the final 4 digits increment within that status group. Examples: `400_0001`, `404_0003`, `500_0010`.
6. Do not renumber existing error codes. Append the next value in the matching status-code group.
7. Keep boundary-specific protocol behavior at the boundary. A2A internals throw `AgwException`; `AgwA2AJsonRpcProcessor` maps those to A2A JSON-RPC errors. Controllers that need custom HTTP responses should catch `AgwException`.
8. Update tests to assert `AgwException.Code` and `StatusCode` instead of framework exception types. Run `dotnet test tests/Agw.Shared.Tests/Agw.Shared.Tests.csproj` after changing exception rules or error codes.

## Web and Desktop Clients

`@agw/web`, `@agw/desktop`, and `@agw/desktop-contracts` share the pnpm Workspace rooted at `src/clients` and use Turborepo for task orchestration. Run all pnpm commands below from `src/clients`; one install covers the complete workspace:

```bash
pnpm install
```

The common workspace-wide commands are:

```bash
pnpm build
pnpm lint
pnpm test
pnpm format
pnpm format:check
```

Turborepo uses its local task cache only; remote caching is disabled. Use a root script when one is available. For a package-specific Web task, use `pnpm exec turbo run <task> --filter=@agw/web`.

### Web Development

```bash
pnpm dev:web
```

The Next.js dev server runs on `http://localhost:3000` by default. `src/clients/web/next.config.ts` rewrites `/api/*` and `/openapi/*` to `BACKEND_API_BASE_URL`, then `NEXT_PUBLIC_API_BASE_URL`, then `http://localhost:30815` unless static export mode is enabled.

Desktop-specific renderer code lives in `src/clients/web/src/features/desktop/`. Shared bridge, runtime, settings, server-profile, and execution contracts live in `src/clients/packages/desktop-contracts/` and are built before either consumer through Turbo dependencies.

Regenerate `src/clients/web/src/api/openapi.d.ts` after backend contract changes with:

```bash
pnpm gen:api
```

### Desktop Live Renderer Development

Start the Web renderer in terminal 1:

```bash
pnpm dev:web
```

After Next.js is ready, start Desktop in terminal 2:

```bash
pnpm dev:desktop
```

### Desktop Packaging

Build either installer flavor from `src/clients`:

```bash
AGW_PACKAGE_FLAVOR=client pnpm make:desktop
AGW_PACKAGE_FLAVOR=full pnpm make:desktop
```

Optionally pass an architecture through to Electron Forge:

```bash
pnpm make:desktop -- --arch=x64
```

## Mobile Client

The Expo app remains a separate npm workspace under `src/clients/mobile/shared`. Follow `src/clients/mobile/AGENTS.md` and run its npm commands from `shared/`.
