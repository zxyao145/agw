# 事件来源与订阅配置简化：实施计划

> **给执行计划的 agent：** 必须使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 按任务逐个实施。步骤使用 checkbox（`- [ ]`）记录进度。

**目标：** 来源使用带前缀的唯一名称并声明事件类型，publisher key 并入 Sources，Webhook 和 HTTP 轮询默认使用 CloudEvents，来源提供器从声明的具名配置中选择，订阅的来源、类型和过滤条件改为表单。

**架构：** 内置来源和 extension 发布方来源成为普通的 `event_source` 行，用 `managed_by` + `managed_key` 识别；订阅只按 `source_ids_json` 选择来源。三个外部入口（Webhook、HTTP 轮询、来源提供器）生成 `CloudEventDraft` 后统一经过 `EventStaging.StageExternalAsync`：替换固定类型、检查类型声明、保存或丢弃。客户端的过滤条件表单与 JsonLogic 之间的转换放在 `@agw/events`。

**技术栈：** .NET 10、ASP.NET Core Minimal API、EF Core（SQLite、PostgreSQL）、CloudNative.CloudEvents 2.9.0、JsonLogic 5.4.3、xUnit v3、Next.js、TypeScript、Node test runner（`tsx --test`）、Playwright。

**设计文档：** `docs/designs/2026-11-15-事件来源与订阅配置简化.md`。执行每个任务之前阅读设计文档的对应章节。

## 全局约束

- 没有兼容性要求。现有事件中心数据由任务 9 的 migration 清空，代码中不保留旧字段、旧接口字段和旧行为。
- 来源名称：后缀匹配 `^[a-z0-9]([a-z0-9.-]*[a-z0-9])?$` 且不包含 `..`，完整名称不超过 200 个字符。前缀：内置 `agw.`，Job 的 Timer `agw.timer.`，用户定时来源 `timer.`，Webhook `webhook.`，HTTP 轮询 `http.`，来源提供器和 extension 发布方来源 `ext.`。同一用户下 `deleted_at IS NULL` 的来源名称唯一。
- 内置来源：`agw.execution`（`ce_source` 为 `/agw/executions`，类型 `agw.execution.completed`）、`agw.notifications`（`ce_source` 为 `/agw/notifications`，类型 `agw.notification.answered`）；`kind = Publisher`，`managed_by = agw`，`managed_key` 等于名称。
- extension 发布方来源：`kind = Publisher`，`managed_by = ext:<extensionId>`，`managed_key = publisher`，名称 `ext.{manifest name}`，名称被占用时依次加 `-2`、`-3`，`ce_source` 为 `/agw/extensions/<extensionId>`，类型声明为 manifest 的 `server.permissions.events.publish`。
- 类型写法：完整类型或 `前缀.*`。用户和 extension 声明的类型不能以 `agw.` 开头。
- 名称检查和插入在应用锁 `events:source-name:{userId}` 内完成。
- 错误码：`EventSourceNameConflict = new(409_0035, "Event source name is already used.", HttpStatusCode.Conflict)`。
- 接口：JSON 接口返回 Bens.Results（`ApiResult.Ok(...)`），标识放在 query 或 body 中，新增路由不使用路径参数。预期失败抛出 `AgwException(ErrorCodes.X)`。
- 当前用户通过 `UserInfoUtil.RequiredUserId` 或 `IUserInfoService` 读取，不增加 `userId` 参数。
- 测试：xUnit v3，命名为 `Method_Condition_ExpectedResult`，使用真实实现和真实的 SQLite、PostgreSQL，不使用 mock、fake 或替身。测试运行时产生的文件保存在测试项目的输出目录或 `.scratch/` 下。
- 注释使用中文和英文两种语言，数量保持克制。时间使用 `DateTimeOffset` 和 `TimeProvider`。
- 格式化：C# 使用 `dotnet csharpier format <修改过的文件>`；客户端在 `src/clients` 下使用 `pnpm fmt`。
- 修改实体、持久化访问、项目引用或 Behavior 之后运行 `dotnet test --project tests/Agw.Architecture.Tests`；修改 `ErrorCodes` 之后运行 `dotnet test --project tests/Agw.Shared.Tests`。
- `tests/Agw.Projects.Tests/Infrastructure/InitialMigrationTests.cs` 检查 `HasPendingModelChanges`，从任务 2 修改实体开始失败，任务 9 生成 migration 后恢复通过。其他测试在每个任务结束时都要通过。
- 过滤参数在本机无效时，先执行 `dotnet build tests/<项目>`，再运行 `dotnet tests/<项目>/bin/Debug/net10.0/<项目>.dll -class "<完整类名>"`。
- migration 只在任务 9 生成，命令见 `docs/1.Development.md`。执行生成命令之前向用户确认。
- 后端接口变化后更新客户端类型：用 `--no-launch-profile --environment Development`、显式 SQLite 连接（`.scratch/events-openapi/agw.db`）、`--AgwDataDir=.scratch/events-openapi/data` 和空闲端口启动 `src/server/Agw.Standalone.Host`，下载 `/openapi/v1.json` 到 `src/clients/packages/api/openapi.json`，再在 `src/clients` 下运行 `pnpm gen:api`。
