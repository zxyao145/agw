# 执行完成后的过程消息折叠与 Worked 耗时展示

## 名词解释

| 名词 | 含义 |
|---|---|
| 执行轮次 | 一次真实用户输入及其后续执行产生的消息，沿用现有用户轮次和流式作用域判定。Agentflow 节点输入不视为新的用户轮次。 |
| Result | 现有逻辑判定为 `result` 的最终结果消息。工具返回、问答结果不等同于 Result。 |
| 过程消息 | 该轮中除真实用户输入、Result 外的可见消息，包括助手说明、推理、工具调用、状态、问答结果和检查点等。 |
| Worked 耗时 | 该轮用户输入的时间戳，到最后一条 Result 时间戳的差值，包含等待时间。 |

## 背景

目前执行过程中产生的消息，在执行结束后仍逐条展示。过程较长时，用户需要滚动较多内容才能找到最终结果。

本次参考提供的截图，在有 Result 的执行轮次结束后，将过程消息收进一个可展开区域，并显示 `Worked for …`，方便用户阅读结果和按需回看过程。

现有代码已经具备统一的 Result 判定、消息时间戳、轮次作用域和共享渲染模型，可以在客户端完成本次需求。

## 设计目标

### 功能目标

1. Web、Desktop、Mobile 使用一致的折叠规则。
2. 每轮执行结束且存在 Result 时，默认折叠过程消息。
3. 用户输入及所有 Result 始终可见；没有 Result 时保持原有展示。
4. 执行失败或被停止后，只要存在 Result，也按相同规则折叠。
5. 支持点击展开和再次收起，保留原有消息内容及操作。
6. 显示 Worked 耗时，重新打开历史会话后仍可计算。
7. 运行中、等待交互、恢复或重连期间保持过程可见。

### 技术目标

- **职责边界**：分组、资格判定和耗时计算放在 `@agw/chat-core`；Web/Desktop 和 Native 分别负责交互与样式。
- **性能**：新增投影逻辑采用线性扫描，时间复杂度为 `O(M + R)`，其中 `M` 为消息数、`R` 为渲染项数；不增加网络请求或计时轮询。
- **渲染成本**：折叠时不挂载过程内容，保留现有虚拟列表。
- **稳定性**：折叠仅改变展示，不修改、删除或重新合并原始消息。
- **安全**：沿用现有会话授权及消息渲染规则，不增加权限入口。
- **可访问性**：支持键盘操作、展开状态朗读和移动端触摸操作。

本次不涉及服务端 SLA、数据库性能指标或新增日志、监控、告警。

## 总体设计

数据流为：

**原始消息与执行状态 → 共享渲染模型 → 轮次折叠组 → Web/Desktop 或 Native 列表**

| 模块 | 职责 |
|---|---|
| `@agw/chat-core` | 识别轮次、判断是否可折叠、收集过程项和 Result、计算与格式化耗时 |
| `@agw/chat-runtime` | 向共享渲染模型传入当前轮次的活动状态 |
| `@agw/chat` | Web/Desktop 的 Worked 入口、展开状态、虚拟列表适配 |
| `@agw/chat-native` | Native 的相同交互及触摸、无障碍适配 |
| Mobile 会话页面 | 将现有工作区执行状态传入 Native 聊天宿主 |

不新增用户配置开关，符合条件时自动应用。

## 数据库设计

无数据库变更。

耗时从已有 `createdAt` 计算；展开状态只保存在当前会话视图中，不写入服务端、数据库或本地持久化存储。无需表结构、索引或 Migration SQL。

## 详细设计

### 1. 按执行轮次折叠过程消息

#### 判定规则

一轮同时满足以下条件时生成折叠组：

- 能确定该轮用户输入及轮次边界。
- 该轮已经结束。
- 至少存在一条可展示的 Result。
- 至少存在一个可展示的过程项。

以下情况保持原有展示：

- 没有 Result。
- 只有 Result，没有过程内容。
- 当前轮次仍在执行、等待交互、恢复或重连。
- 历史分页尚未加载到用户输入，无法确定轮次边界。

正常完成、失败、停止采用同一规则。断线本身不视为执行结束。

#### 分组算法

1. 沿用现有真实用户输入判定和流式作用域，确定每条消息所属轮次。
2. 复用现有可见性过滤、工具聚合及 Result 判定。
3. 在轮次内收集真实用户输入、Result 和过程渲染项。
4. 对符合条件的轮次，将过程项收进一个折叠组。
5. 输出用户输入、折叠组及所有 Result；其他轮次保持原样。

折叠组放在该轮第一条 Result 前。过程项内部保持原顺序，多个 Result 之间保持原顺序。

系统已经隐藏的控制消息继续隐藏；展开过程区不会使其重新出现。保留现有跨消息工具调用匹配行为，避免分组造成工具详情丢失。

### 2. Worked 耗时计算

采用已确认的口径：

```text
durationMs = 最后一条 Result.createdAt - 用户输入.createdAt
```

这里使用现有消息时间戳，不将它解释为服务端精确执行耗时，也不使用浏览器当前时间补算。

| 情况 | 展示 |
|---|---|
| 小于一分钟 | `Worked for 8s` |
| 一分钟至一小时 | `Worked for 17m 39s` |
| 一小时及以上 | `Worked for 1h 2m 3s` |
| 有效时间差不足一秒 | `Worked for 0s` |
| 时间缺失、无效或倒序 | `Worked` |

按毫秒差向下取整到秒；小时不按天截断。按时间戳表示的绝对时间计算，支持 `Z` 和时区偏移，不受客户端显示时区影响。

多条 Result 使用该轮消息顺序中的最后一条，不通过取最大时间戳掩盖异常数据。

### 3. 三端折叠交互

#### 折叠状态

- 使用灰色 `Worked for …` 文字和紧邻文字的向右箭头。
- 入口与 Result 正文左侧对齐，使用现有字体、主题颜色及细分隔线。
- 合并现有 Result 顶部分隔样式，避免双重分隔线和过大留白。
- 默认不展示过程内容。

#### 展开状态

- 点击入口后，箭头朝下，在入口下方展示过程内容。
- 再次点击入口收起。
- 复用已有消息组件，不重新实现 Markdown、工具详情、问答结果或检查点。
- Result 保持可见，原有复制、时间及其他操作保持可用。

#### 状态保存与滚动

展开状态由会话列表宿主持有，以会话和轮次的稳定标识关联：

- 流式更新、普通重渲染和虚拟列表卸载不重置已展开状态。
- 切换或重新打开会话时默认折叠。
- 某轮重新进入活动状态时强制展示过程，结束后重新默认收起。
- 展开或收起后更新列表测量；手动查看过程时避免自动滚到底部。
- 用户已停留在底部时，执行结束后的自动折叠继续保持结果可见。
- 保持 Desktop 用户输入导航与实际虚拟行位置一致。

Web/Desktop 使用可聚焦按钮及 `aria-expanded`；Native 使用 `Pressable`，提供按钮角色和展开状态，触摸区域至少为 44×44。

### 4. 执行状态与历史兼容

共享渲染模型增加当前轮次活动状态参数。各宿主根据已有执行、等待交互、恢复和重连状态计算并传入。

- 活动状态只阻止当前轮次折叠，不影响此前已完成轮次。
- 静态历史默认按已结束处理；存在活动执行时，宿主必须显式传入。
- 历史加载或执行恢复尚未确认时，不提前折叠当前轮次。
- 旧消息没有时间戳时，满足其他条件仍可折叠，入口只显示 `Worked`。
- 分页加载补齐用户输入后，重新计算分组与耗时。
- 回放、重复消息合并和检查点恢复继续沿用现有身份规则，避免重复入口或跨轮混入。

## 接口文档

### HTTP / WebSocket 接口

无新增或修改。域名、环境、认证授权、请求头、响应头及消息协议均保持现状。

### 客户端共享接口

#### 渲染模型构建参数

为 `BuildConversationRenderModelOptions` 新增：

```ts
isCurrentTurnActive?: boolean;
```

| 属性 | 说明 |
|---|---|
| 默认值 | `false`，用于静态历史 |
| `true` | 当前轮次尚未结束或结束状态尚未确认，不生成折叠组 |
| 接入方 | Web 聊天宿主、共享 Conversation Controller、Native 聊天宿主 |

#### 渲染项类型

为 `ConversationRenderItem` 增加 `work-summary` 分支，沿用基础渲染项的稳定 `key`、对齐及宽度属性，新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | `"work-summary"` | 执行过程折叠组 |
| `durationMs` | `number \| null` | 可计算的耗时，无法计算时为 `null` |
| `items` | 普通过程渲染项数组 | 不包含用户轮次输入、Result 或嵌套折叠组 |

展开状态不进入共享模型，由平台列表宿主管理。所有消费该联合类型的渲染器同步支持新分支；不修改服务端 DTO 或生成的 API 类型。

## 测试计划

### 单元测试

| 用例名 | 前置条件与操作 | 预期 |
|---|---|---|
| 完成后生成折叠组 | 输入、过程、Result 齐全，当前轮次非活动；构建模型 | 输入和 Result 保留，过程进入一个组 |
| 活动轮次不折叠 | 相同消息，活动状态为 `true` | 保持原展示 |
| 无 Result 不折叠 | 只有输入和过程；构建模型 | 不生成组 |
| 无过程不生成空入口 | 只有输入和 Result | 直接展示 Result |
| 多轮隔离 | 两轮均含过程和 Result | 各自分组，不混入另一轮消息 |
| 多 Result 保留 | 一轮含多个 Result 及穿插的过程消息 | Result 全部可见且顺序不变 |
| 工具返回不触发折叠 | 只有工具返回或问答结果，没有 Result | 不生成组 |
| Agentflow 节点输入不拆轮 | 一轮含节点输入及 Result | 节点输入按现有语义归入过程 |
| 分页边界不完整 | 缺少用户输入；随后补齐历史 | 补齐前不分组，补齐后正确分组 |
| 耗时正常与边界 | 构造秒、分、小时、跨日及不同偏移时间戳 | 格式和值正确 |
| 耗时异常 | 时间缺失、无效、倒序 | 耗时为 `null`，显示 `Worked` |
| 原始数据保持不变 | 构建前后比较输入消息 | 内容和顺序未被修改 |

### 集成测试

1. **执行生命周期**
   - 执行中先收到 Result，过程仍可见。
   - 收到完成、失败或停止状态后自动折叠。
   - 无 Result 的异常结束保持原样。

2. **等待与恢复**
   - 等待用户输入、审批及重连期间不折叠。
   - 恢复执行后继续显示过程。
   - 历史加载和恢复状态确认后应用正确规则。

3. **Web/Desktop 交互**
   - 鼠标及键盘可展开、收起。
   - 虚拟列表滚动卸载后，展开状态保持。
   - 展开后工具详情、检查点和消息操作可用。

4. **Native 交互**
   - 触摸入口可展开、收起，无障碍状态正确。
   - 列表高度更新正常，手动展开不被自动滚动打断。
   - 移动端布局不溢出。

### 回归测试

- Result 的 Markdown、JSON、计划内容、复制和时间展示。
- 工具调用分组、问答结果、检查点恢复和重复事件回放。
- 长会话滚动、历史分页、Desktop 用户输入导航。
- 切换会话后不继承其他会话的展开状态。
- 浅色、深色主题及窄屏布局。

运行受影响包的测试、类型检查、lint 和格式检查，以及 `pnpm test:boundaries`。完成三端交互验收后，以“结果始终可见、过程可完整回看、活动轮次不误折叠”为最终通过标准。
